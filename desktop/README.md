# yangbin AI Agent 桌面客户端

Windows x64 便携版：解压完整文件夹，双击 `yangbin AI Agent.exe`，登录现有网站账号。在 Coding Agent 的项目选择中添加本机目录，或为已有本机项目选择它在电脑上的文件夹。

0.4.0 的 Coding 任务读取所选目录并在私有候选中修改文件，原目录保持不变；审阅后可下载补丁自行合并。候选模式不启动本机程序。无需单独下载运行器、安装用于连接的 Node.js、填写地址或连接码。项目自身需要的 Python、Java、Node.js 等开发环境仍取决于项目。模型及账号继续使用网站服务，客户端需要联网。

模型修改候选文件遵守所选审批策略。以下为历史0.2.0运行模式说明，不代表0.4.0候选任务支持启动程序：0.2.0 的“全部允许”在提交时进行一次本轮原生授权，此后该轮文件操作、启动、预览和停止程序不逐次确认；任务结束、取消或超时后授权失效，界面恢复“按需确认”。其他模式保留命令原生确认。命令以当前电脑账号运行，不是操作系统隔离环境。关闭客户端会停止它启动的程序。右上角 VS Code 入口使用实际绑定目录，无需再输入路径。

本机目录绑定按站点和登录账号存放在客户端用户数据目录；目录完整路径不作为创建项目参数发送服务器。文件内容仍会随任务交给已有 Coding 服务和模型处理。客户端不打包模型密钥、服务器凭据、用户项目或登录会话。

当前桌面版本为 0.4.0。配套网站更新后，可以在侧栏「我的博客」写 Markdown、预览并保存草稿。手机登录同一账号即可继续写作。公开发布后可在阅读页复制免登录链接；点击「导入知识库」后可到「我的知识库」检索。

网站登录页、侧栏「下载客户端」和客户端「应用 → 检查更新 / 下载客户端」均可打开下载页。更新时结束任务、退出旧客户端，完整解压新版再启动。

当前为未签名的便携版本，无自动更新。Windows 可能提示未知发布者。

## 开发与打包

Node.js >=22.12；`npm ci` 安装固定 Electron 45.1.0，`npm start` 打开客户端，`npm test` 执行本机文件/进程检查，`npm run package` 生成 `out/yangbin-ai-agent-0.4.0-win32-x64/`。安装器可能在首次启动时下载 Electron；受限网络下须正常配置网络，并按官方包内 checksums.json 校验，不跳过校验。

桌面加载固定 HTTPS 产品地址。开发模式可以通过 `YANGBIN_DEV_ORIGIN` 指定 loopback HTTP 测试服务，`YANGBIN_DEV_DATA` 指定隔离用户目录；打包版忽略这些变量。原生文件和进程代码复用产品模块，打包脚本只复制明确列出的源码。

## 边界

渲染进程启用 sandbox/contextIsolation，关闭 Node 集成；IPC 校验主窗口、主 frame 和固定来源，并复核登录账号。文件操作限定原生选择的项目，保留保护路径、链接拒绝、读后修改和外部冲突检测。任务工具操作在执行前校验服务器任务、项目绑定、最新轮次和请求有效期；命令确认后再次校验。请求编号复用只返回既有结果，不能重放操作。

工程测试采用模拟账号/API/模型步骤、替代原生选目录与确认对话框；真实桌面引擎、磁盘文件、子进程和 HTTP 预览均实际执行。它不是本轮真实模型质量评测或原生目录选择器人工验收。

安全设计参考 [Electron 官方安全指南](https://www.electronjs.org/docs/latest/tutorial/security) 与 [进程隔离文档](https://www.electronjs.org/docs/latest/tutorial/sandbox)。

0.2.1 不包含本机持久化工具日志：本机崩溃恢复仍为人工检查，M041 服务端文件恢复保证不能外推到本机进程。

## 0.4.0 工作台同步

本版增加独立候选与持久回执：支持的转交任务先修改私有候选，可核对回执、下载补丁后合并；当前候选任务不会直接写入绑定目录。匹配失败在明确未写入时可继续纠正，结果未知的写入不会自动重放。应用内切到Chat或设置保留Coding连接；关闭窗口、退出账号与休眠仍需要恢复核对。前端、Java、Coding运行时和客户端需使用配套版本。

打包可用环境变量 `YANGBIN_PACKAGE_DIR` 指定新的绝对输出目录；已存在的目录会拒绝覆盖。
