# 2026-11-14 系统 Bug 修复

本轮负责 yangbin AI Agent 系统 Bug，先修复 11 月 14 日三版复盘已确认的两个 P0。基线是 `worktrees/yangbin-repair-pairs`（HEAD `ebfed754`）现有未提交 v1，原有修改全部保留。没有修改已封存的评测源码、补丁、1500 份评分或账本。

## A：编辑失败与实际副作用分开结算

执行端错误新增独立 `mutationReceipt={effect,phase}`。唯一匹配、内容、路径等明确写前校验失败为 `NO_EFFECT/VALIDATING`；创建文件、目录、暂存或进入提交后不确定为 `UNKNOWN`；内容已提交后的清理或展示异常为 `COMMITTED/COMMITTED`。不按错误文字猜测，也不自动重放未知操作。

覆盖浏览器 `LocalDirectory`、桌面 `NativeDirectory` 和实际候选写入 `CandidateWorkspace`。Electron 通过数据 envelope 保留错误字段；前端、Java `LocalResult`、Node `LocalToolRuntime` 按请求传递与验证。新字段和原候选持久回执 `receipt` 分开。Agent 在明确未写入时允许模型纠正，缺失/畸形回执仍停机；COMMITTED 错误仍作为工具错误展示，不能当作候选已确认或任务成功。候选 PREPARED 的核对、旧写者和下载门槛保留。

关联修复：已派发写入失败或结果未知时让旧验证失效；成功回执后立即取消仍保留已提交事实。每个请求独立结算，乱序返回不串用状态。

## B：探索测试与固定验收分开

可信 Node/pytest 运行器增加结构化断言/执行异常分类。自建测试的夹具/执行异常可修正，不立即冻结；尚无固定定义的新测试不再误报 TEST_CHANGED。参数或审批拒绝不注册必验目标；无快照的环境失败不继承旧候选哈希。已有显式或已核验定义仍保护，旧失败不会被相邻通过覆盖。

边界：首次核验前改过的旧测试与真正新测试，目前仍无法完整区分。自建测试自动晋升的条件是运行器报告断言失败且无已知非测试修改，这不证明断言语义与 issue 一致。Django 尚无结构化异常类别时保守不建立红基线。

## 独立开关

默认开启 `CODING_MUTATION_RECEIPTS_FIX=on` 与 `CODING_TEST_LIFECYCLE_FIX=on`，可分别设为 `off`。Java 显式透传并校验取值；Spring 配置分别为 `app.coding.mutation-receipts-fix`、`app.coding.test-lifecycle-fix`。开关用于比较各自的结算/生命周期逻辑，不表示当前整个工作树回到了历史冻结版本。
