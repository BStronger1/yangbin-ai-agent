# Coding 工作台切页中断修复

日期：2026-11-14。开发位置：`worktrees/yangbin-repair-pairs`，保留前轮 A/B 系统修复及其余已有修改。

## 故障与原因

本机 Coding 任务依赖页面领取 `/local-files` 请求、调用设备目录并回传结果。旧页面卸载时断开目录和运行器、清空内存回执并停止轮询；执行器等待结果超时后停止。普通浏览器重新挂载还会产生新的 clientId，与原任务绑定不符。已领取但未知结果的操作不能重复领取，因此回来后无法简单恢复。当前开发树另有阻止运行中离页的守卫，旧构建实测点击 Chat 被阻挡。

服务端 Coding 任务本身由后端独立执行，切页不应当取消；页面也需要保留或重新同步原任务展示。

## 修复

- App 仅缓存 Coding 工作台实例；`/coding` 与旧 `/super-agent` 各自独立，最多两个。缓存按登录账号隔离，登出或换账号销毁旧上下文。
- 工作台保留自己的路由快照。Chat、设置等页面的 query 不再触发 Coding 清空会话或切模式，本机 clientId、目录、领取记录、回执与执行泵持续存在。
- 应用内切页只隐藏界面，不再阻止导航或断开任务。返回时刷新状态与模型目录；运行中本机任务不会被别的 session/project/transfer 链接替换，裸 Coding 链接恢复活跃任务。
- 任务创建、提交与转交的异步响应只更新所属工作台；用户已离开时不会把路由拉回 Coding，也不会重复提交。
- 停用工作台时释放弹层的键盘和焦点监听，隐藏审批不会抢占设置页面输入。实际关闭窗口的本机运行提醒仍保留。
- 旧轮询返回后仍安排当前会话轮询，避免切换服务端会话时丢失后续刷新。

本轮没有增加工具超时，没有放开重复领取或未知副作用重放，也没有修改后端任务、模型、预算及候选确认规则。

## 边界与接续

修复覆盖同一应用窗口内的页面切换；刷新、关闭窗口、设备休眠或退出账号仍会中断依赖该窗口的本机执行连接，不能据此承诺离线后台执行。已中断且结果未知的旧操作仍需核对回执/文件后新建一轮。

当前为本地源码修复，尚未部署或生成 Windows/iOS 分发包。验收完成后如需发布，应按实际发布树与账号空闲检查部署，不混入其他评测候选。
