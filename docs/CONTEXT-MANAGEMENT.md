# Coding 上下文管理

版本：layered-v1，2026-10-22。针对基于 pi 1.3.0 的服务适配层，保持上游摘要、会话持久化及工具调用循环；不复制桌面客户端的本机权限模型。

## 分层与来源

1. 系统规则、账号权限、工具审批与预算仍由服务端配置和校验控制，不能由记忆或摘要覆盖。
2. pi 按可用上下文预算保留近期消息并生成摘要，不以固定5/15轮删除历史。近期完整轮次和错误结果不被本轮额外工具裁剪替换。
3. 用户提交的原始需求单独存档；首轮及最近已移出的部分请求以受限原文摘录和opaque引用重新提供给模型。最新用户消息保持在末尾，旧记录注明可能被后续修改。不宣称自动识别/永久保留每条关键要求。
4. read/list/bash的有界原文超过2048bytes时存快照。长内容按页展示；两个完整assistant回复之前的已归档成功结果可缩成短摘录，原始历史仍保留。工具输出始终是未经信任的证据。
5. recall只读本session的快照或索引；文件变化后原快照不更新，检查当前文件应read。recall接受随机ID，不接受路径，不自动重新运行工具。

## 边界与失败

- 文件读写上限64KiB，工具原始捕获保留既有64KiB边界；未捕获的尾部不能凭空恢复，返回明确标志。read可按行及行内字符继续，不静默丢失页尾。
- 存档采用随机ID、内容hash、私有权限、原子发布、有限条数/正文配额和链接拒绝。它位于账号/项目所对应sessionDir内，模型不能指定另一账号目录。不是对同OS用户恶意进程的强隔离。
- 512条/8MiB满后不删历史；请求保护显式降级，仍用pi既有历史和摘要继续。新请求仅有临时摘录，没有假造可recall引用。大型旧会话首次接入同样遵守这一规则。
- 存档损坏或未知文件失败关闭；归档失败的工具返回实际已执行结果和不可恢复提示，不能误导模型重跑命令。取消会检查AbortSignal；已完成的文件修改不自动回滚。
- 崩溃恢复只处理能证明无活跃写者的本机锁和未提交临时文件；未知/活跃/异机锁拒绝自动清理，保留已提交记录。
- 摘录有硬bytes预算，并在pi的reserve中额外留空间；这不是精确tokenizer。请求/摘要/回读的实际模型调用都仍需共享预算许可。

## 验证口径

见 [离线任务对照](CONTEXT-EVALUATION.md)。真实SDK、真实文件与模拟模型可验证协议/恢复机制，不能证明真实模型任务成功率提高。新工具schema和摘要可能增加输入、请求数和延迟。SWE-bench/Terminal-Bench等真实任务基准尚未运行；启用终端仍取决于目标机独立隔离验收，记忆改进不扩大任何工具权限。
