# M031 A2A task adapter

Date: 2026-10-22. This workstream implements a protocol adapter around the shared TaskStore/BudgetLedger/Executor. It does not create another product task runtime, expose a public agent, deploy a server, or call a paid model.

## Frozen compatibility

- Official A2A specification **1.0.0**, wire **1.0**, JSONRPC binding and SSE.
- Exact dependencies: `@a2a-js/sdk@1.3.0`, `express@5.2.1`; shared controlled transport uses existing undici 8.10.2.
- Node used for validation: **24.19.0**; project minimum 22.19.0.
- Sources: [official specification](https://a2a-protocol.org/v1.0.0/specification/), [official JavaScript SDK](https://github.com/a2aproject/a2a-js), [v1 migration](https://github.com/a2aproject/a2a-js/blob/main/docs/migration-guide.md).

The adapter uses supportedInterfaces and wire 1.0 methods through the official SDK. It does not use the former message/send method or legacy kind-shaped v0.3 payloads. It does not enable the SDK's optional v0.3 compatibility.

## Inbound server

`createA2aServer({url,authenticate,taskStore,executor,budget,permissions,testLoopback?,maxDurationMs?})` returns `app, handler, card, close`.

Mount app behind the existing authenticated gateway. authenticate(req) must validate credentials and return a trusted `{identity, principalId, permissions}`. identity is the shared contract; incoming message metadata cannot supply it. A new task gets server-generated child task/agent IDs and a server-generated context ID. Configured server permissions intersect the authenticated principal's permissions.

Task status, cancellation, artifact metadata and ownership use the injected shared TaskStore. Remote principal binding is additionally required for every GetTask, CancelTask and SubscribeToTask. The account/project check still runs in TaskStore. Read failures return task-not-found instead of disclosing another scope.

Executor receives `{identity,prompt,permissions,signal,budget,emit,context:[]}`. It must perform any model work through the same budget and existing approval controls. The adapter reserves only one local delegation admission token, settles it with known zero model use after local dispatch, and leaves unknown outcomes reserved; it is not a substitute for the executor's model reservations. Executor progress accepts only `{type:'progress',phase}` and stores a bounded phase label, not hidden reasoning.

Supported: authenticated Agent Card, text SendMessage, SendStreamingMessage, GetTask, CancelTask, SubscribeToTask, bounded task listing and controlled artifact references. Initial stream Task is followed by artifact/status events; terminal state never resumes. Existing terminal tasks cannot be cancelled. Duplicate message IDs with the same scope and text return the original task; changed payloads are rejected.

Explicitly unsupported: webhook/push notifications, extended Agent Cards, caller-selected tenants/contexts/reference tasks, additional input on an existing task, nontext inputs, external file uploads, gRPC/REST binding, paginated task lists and time filters. Those methods/parameters are rejected, and optional capability flags remain false. Listing is limited to 100 results; larger result sets must be narrowed instead of falsely returning an incomplete page.

Task artifacts are references to existing controlled storage; no new arbitrary URL route is added. Actual downloads must continue through integration's account/project artifact authorization.

The supplied TaskStore and adapter replay/principal maps are process-local. Production restart persistence/reconciliation is an integration concern: do not automatically replay inbound requests after restart. close cancels active tasks and propagates AbortSignal to executors. Executors that ignore cancellation must not mutate workspaces after cancellation; the adapter stops accepting their results.

## Outbound remote executor

`createRemoteAgent({identity,remoteId,url,cardUrl,expectedCardHash,credentialProvider,authorize,budget,storeArtifact,remotePermissions,...})` returns `discover,get,cancel,execute,close`.

- Bind the exact endpoint, Card URL, remote ID, Card hash and tool permission ceiling in trusted server configuration.
- The Card must declare exactly one JSONRPC interface at the pinned endpoint, wire 1.0 and streaming. Required unsupported extensions, endpoint drift and changed Card hashes fail closed. Card descriptions are never promoted into system prompts.
- Hash a normalized SDK Card with exported cardDigest. Hash acceptance must be a trusted registration action; never auto-accept drift from a model request.
- credentialProvider returns `{accountId,projectId,remoteId,endpoint,expiresAt,accessToken,permissions}`. Token grants must exactly match configured remotePermissions; configured permissions must be a subset of the parent's execute request.permissions. This relies on the remote issuer enforcing its declared token grants. A2A cannot itself sandbox an untrusted remote organization.
- Each instance accepts one active execution at a time. Separate instances may share the same global budget for team concurrency.
- All network traffic uses the shared exact-URL HTTPS/DNS/redirect/body/time guard. Numeric loopback is a trusted test-only opt-in. No authenticating-fetch retry helper is used; repeated SendMessage/SendStreamingMessage IDs are refused.
- Shared authorize runs before SendMessage, binding the Card hash and prompt hash. Card is rechecked after approval. Global budget reserves positive conservative tokens and known monetary ceiling (if available); remote usage remains null, never fabricated from text or Card claims.
- Remote task IDs are bound after the first stream event. Subsequent IDs must match; get/cancel reject unobserved IDs. Stream must end with an actual terminal state. Missing terminal, post-terminal updates, excessive events, oversized artifacts, auth failure and unsupported interruption states fail closed.
- Remote artifact text/data is untrusted evidence. URL/raw file Parts are rejected; URLs embedded in text/data are inert and are never fetched. storeArtifact must persist the evidence through existing controlled artifact storage and return a valid local artifact reference. Bearer-token echoes are redacted before storage.
- Abort/timeout sends best-effort CancelTask when the remote ID is known; it cannot prove remote side effects stopped. Unknown outcomes retain budget. No automatic retry or resume occurs.

## Validation

Command: `node --test coding-agent/test/a2a.test.mjs`.

**11/11 passed**, Node 24.19.0, 2026-10-22. Tests use real local HTTP/SSE:

1. **Official SDK client → this server adapter:** task/result/query, account isolation, authentication, terminal cancellation rejection.
2. Streaming cancellation into the shared TaskStore and executor.
3. Duplicate request, changed payload, unsupported push and untrusted context.
4. **This client → independent official DefaultRequestHandler + InMemoryTaskStore reference server:** full task/status/artifact stream, controlled storage and query.
5. Arbitrary remote artifact URL rejection.
6. Approval denial, malicious Card endpoint and Card drift.
7. Explicit remote cancellation, UNKNOWN usage accounting.
8. Budget denial and token grant mismatch before dispatch.
9. Parent permission ceiling and duplicate-dispatch prevention.
10. Credential echo redaction.
11. Incoming URL Parts, unknown task IDs and tenant selection rejection.

The first test iteration exposed incorrect Express router mounting, Card normalization of SDK undefined defaults, and duplicate case-insensitive version headers in the reference client's fetch wrapper. These were fixed before the passing run. Cancellation now triggers on a received WORKING event rather than a timing assumption.

This validates the implemented subset against independent official components; it is not full A2A conformance certification, model quality evidence or a public deployment claim. Integration owns API/router/lock changes, trusted credential storage, remote registration UI, durable restart semantics and deployment.
