## Entry points and trusted configuration

```js
import { createTeamRuntime } from './teams/runtime.mjs';
import { createLocalExecutor } from './teams/local-executor.mjs';
const executor = createLocalExecutor({
  runAgent, env: trustedModelEnvironment,
  budgetManagedByRunAgent: true, // integration runAgent reserves the shared ledger
  approve: null,               // parent process handles pending approvals
  onGate: (gate, identity) => registerModelGate(gate, identity),
  onTools: (tools, identity) => registerTools(tools, identity),
  onEvent: (event, identity) => forwardToTrustedParent(event, identity),
});
const runtime = createTeamRuntime({
  store, ledger, executor, rootDirectory: isolatedTeamRoot,
  emit: event => publishSanitizedProgress(event),
  maxConcurrency: 2, maxCorrections: 1, timeoutMs: 120000,
});
const result = await runtime.execute({
  identity: trustedIdentity, permissions: ['read','list','write','edit'], signal,
  contextArtifacts: [{name:'requirements.txt', content:'Explicitly selected input only'}],
  members: [
    {id:'analysis',role:'manager',prompt:'Analyze requirements',permissions:['read'],writePaths:[],dependsOn:[]},
    {id:'implementation',role:'worker',prompt:'Implement the artifact',permissions:['read','write','edit'],writePaths:['result.txt'],dependsOn:['analysis']},
    {id:'review',role:'reviewer',prompt:'Independently check requirements and artifacts',permissions:['read'],writePaths:[],dependsOn:['implementation'],reviewOf:'implementation'},
  ],
});
```

Without integration-owned budget handling, leave budgetManagedByRunAgent=false: LocalExecutor bridges every ModelGate request and settlement to the same ledger. This includes summaries because the existing gate covers all model HTTP. Never use both mechanisms concurrently. A finite monetary limit with unknown prices fails closed. Unknown usage keeps the complete reservation. The default approval callback rejects; approve:null forwards raw approval events and waits for the trusted parent. onTools runs after minimum-permission and file-ownership wrappers. onEvent contains raw events for trusted IPC and must not be broadcast unfiltered to other accounts. Child executionContext is `{budget:ledger,identity,permissions}`.

`execute` returns `{status,teamTaskId,members,artifacts,budget}`. Each artifact includes id/taskId/name/size/sha256 and internalPath; strip internalPath from public JSON and resolve downloads through an authenticated owner-scoped server. No remote URL is accepted. TaskStore records child identity, parent relation, state, progress and controlled artifact refs. Blocked tasks have a recorded child identity and failure-before-execution reason.

## Execution and trust boundary

A validated plan has 2–12 members. Child identity is generated by the host; permissions are a subset of the parent. Every attempt, including corrections and reviews, has a different task/agent identity, workspace and session directory. Context contains only explicit text artifacts and dependency-produced files, never full parent conversation or all long-term memory. Each input file is at most 64 KiB; at most 48 files and 512 KiB are admitted to an attempt. Protected paths and common credential forms reject before copying; pattern checks are not comprehensive secret detection.

LocalExecutor invokes the existing runAgent, with shell disabled. Actual tools enforce permissions and writePaths; approval is still required for writes. Distinct attempts use independent workspaces and a logical case-insensitive ownership lock prevents concurrent writers to the same declared path. Files are staged only; the runtime never copies them back to the user's main workspace. Missing declared output is failure. Artifacts are read from actual regular files, checked for links/size and hashed. Dependency reads recheck hash before use.

DAG dependencies and bounded parallel fan-out are real asynchronous executor invocations. A reviewer has no write tools, must read every provided artifact through actual successful tool calls, and must return strict JSON `{passed:boolean,findings:string[]}`. A worker's claim of success alone cannot pass review. A negative verdict may trigger 0–2 fresh producer/reviewer attempts; default is one. With automatic correction, the reviewer must be a leaf and the producer's only direct consumer, preventing concurrent consumers from using superseded artifacts. With maxCorrections=0, ordinary DAG fan-in/out is permitted. Missing reads or malformed verdict fail rather than trigger model retries.

Root cancellation propagates to all child tasks and abort signals; no later dependent starts. Cancellation of a child blocks its dependents. Deadline uses the same cancellation path. Partial and blocked results remain visible. There is no retry of unknown external outcomes or provider failures. A correction is a new explicitly bounded artifact revision in a new staged workspace, not a replay of external side effects.

The executor boundary is `executor.execute(context)`. This module implements the local executor; a future remote A2A adapter must preserve authenticated identity, approvals, ledger and controlled artifacts, and must not trust a remote `readPaths` self-report as independent inspection evidence. No A2A integration or public discovery is claimed here. Plan decomposition is currently trusted server input; the manager member performs actual analysis but cannot change the DAG or grant permissions through text. Bounded group discussion is not implemented.
