# 持久会话与实时规划验收（2026-10-16）

本轮针对 `code/yu-ai-agent`，不涉及顶层 Recall Agent。已部署至 Turing 原实例，管理员账号与原有数据保留。

代码提交 `2ea7b68` 的 [GitHub CI](https://github.com/BStronger1/yangbin-ai-agent/actions/runs/38778339202) 全部成功：38 项 Java、20 项 Python 及前端构建。

## 实际验收

- 本地定向测试覆盖会话 JSON 重载、最多 20 条窗口、账号/模式隔离、工具消息往返、生成中禁止删除、损坏文件显式报错；HTTP 测试验证普通用户不能读取或删除其他用户会话。
- 外部接口模拟验证所选日期、缓存、超出 16 天、天气故障、重名城市、未知地点编号拒绝；既有工作台与权限测试回归通过。
- Turing 真实查询上海：取得所选日期天气与 10 条 Photon / OpenStreetMap 地点候选；真实模型生成了引用候选 placeId 的方案。
- 保存测试对话后随修复部署停止并重启应用进程；从磁盘恢复历史，真实模型正确回复此前的测试口令。方案依据快照在重启前后完全一致。
- 本轮合计 4 次真实模型请求（3 次聊天、1 次规划），不是质量 benchmark。额外一次聊天来自验收脚本对 SSE 分块的错误判断；已修正为拼接内容，并核对持久化的完整回复。
- 浏览器验证历史选择、刷新恢复、方案来源、独立实时预览和 390px 手机布局；无 JavaScript 页面错误。测试用会话与方案清理，不影响原有资料。
- 实际 PDF 导出、两页渲染检查通过。首次导出因外部店名含韩文触发 iText 单一中文字体空 glyph 错误；增加中日韩回退及显式 Unicode 缺字标记，新增多语言回归测试。

## 来源与失败记录

- Open-Meteo 天气 / GeoNames 城市定位；Photon 检索 OpenStreetMap 的地点记录。
- Overpass 主节点超时、Private.coffee 返回 500、VK 节点返回 504，因此正式实现改用实测可用的 Photon。接口可用不等于 SLA，后续故障必须显示不可用，不伪造地点。
- 地名库含同名村镇，先匹配城市级记录；仍有歧义时提示补充省份，不默认取第一条。
- 来源快照随方案版本保存，含查询时间、坐标、预报日期、候选地点编号及来源 URL；不是商家营业状态或实时价格核验。

## 边界与复验

- 持久化的是恋爱问答各模式的近期上下文，不是自动归纳的跨会话长期记忆，也不是无限历史；超级智能体仍是单次任务。
- 最多 20 条消息；同一进程内原子文件与并发保护，未验证多实例部署。旧版已丢失的内存会话不能恢复。
- 中国城市定位点周边约 3 公里，最多 12 个候选；不提供用户定位、路线/交通耗时、商家价格或当天营业状态。
- 未来 16 天的天气预报可能变化；10 分钟缓存；免费服务有使用范围与可用性限制。
- 复验脚本：`deploy/turing/memory-live-smoke.py prepare` → 重启本实例 → `verify` → 浏览器 `memory-live-browser.py` → `cleanup`。prepare/verify 会调用真实模型；不要把脚本放入无人值守免费单元测试。
- 本轮服务器证据：`logs/memory-live-verification.json`、`logs/live-evidence-plan.pdf`、`logs/screenshots/`；本地截图/PDF副本位于工作区 `tmp/memory-live-evidence/`，未提交 Git。
