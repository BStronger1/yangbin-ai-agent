# 页面加载性能修复（2026-10-27）

代码优化已部署并通过源站及公网验证。期间遇到的 Cloudflare Tunnel 1033 已在按原配置重连及网络恢复后消失，失败记录保留。公网链路仍会波动，不能承诺首次访问始终达到固定速度。

## 定位与修改

同一服务器 Chromium、临时正常账号的修复前测量：公网登录页首次可见 9125 ms；通用助手两次 8531/9681 ms，Coding 两次 14117/16208 ms，技能页两次 10658/14938 ms。内网登录页 1561 ms。每页仅两次观察，不是稳定性能基准。公网已有 Cloudflare 压缩，但静态资源 `no-store` 导致相同 JS/CSS 重复传输，且首个页面模块等待会话检查后才加载。

- 仅对 `assets/` 下带内容版本名的程序资源设置一年 immutable 缓存；HTML、会话、数据和 PPT 私有路由保持不缓存。
- 构建阶段生成 gzip 文件，由现有文件服务按客户端能力选择；无需每次请求重新压缩，内网也可使用。
- 初始路由代码与会话检查并行下载；权限检查通过前不渲染工作空间，也不请求其私有数据。
- HTML 和应用启动阶段显示加载反馈；页面模块失败时提供重新连接按钮。

## 公网故障与恢复记录

修复后首次公网复测无法看到登录表单。匿名诊断在服务器和用户本机均得到 HTTP 530 / Cloudflare 1033，未加载应用资源。初次复测临时账号已停用、邀请已撤销；负结果保留。

原 connector 虽本地报告 4 条连接，但公网仍不可达。只对本项目命名隧道按原配置执行优雅重连；原进程约 30 秒退出，首个等待命令在边界超时返回 1，随后用既有启动脚本启动成功。新 connector 的内置预检显示两个区域 DNS/API 可达，但 UDP QUIC 与 TCP HTTP/2 均失败；进一步对 DNS 返回的 20 个官方 IPv4 节点执行 TCP 7844 探测，20/20 超时。没有更改防火墙、DNS、隧道凭据、协议配置或其他应用。不能凭超时断言具体是哪一级防火墙或网络设备故障。

恢复条件：服务器至 Cloudflare 官方节点的 7844 出口/回程可达。参考 [Cloudflare 官方连接排障](https://developers.cloudflare.com/tunnel/troubleshooting/)。已有 connector 保持按原逻辑重试；没有新增后台监控或额外机器。

网络随后恢复，connector 4 连接、后端200，本机浏览器公网登录200且页面可见；该本机独立首次访问仍耗时14596ms。使用新标签 `after-reconnected` 完成同服务器/同浏览器/同访问顺序复测：登录6079ms；助手3702/3567ms；Coding2397/1385ms。重复访问助手11/11、Coding10/10静态资源传输为0，会话仍no-store。每页仅两次，且前后网络状态变化，改善不能全部归因于代码；缓存命中属于直接证据。

技能页首次测量选择器包含通用main，误匹配新增加载提示，559/844ms作废，不能宣称技能页亚秒完成；已改为data-testid=skill-hub，独立补验 `after-skills-verified` 为2642/1721ms（修复前10658/14938ms），临时账号停用/邀请撤销。所有失败和成功的标签分别保留，不覆盖或拼接为一轮结果。
