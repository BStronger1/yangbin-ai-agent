# 运行治理与安全边界

本文描述当前源码提供的控制，以及自部署时需要验证的边界。代码和测试用例存在不代表某个站点已完成发布、容量验收或安全认证。部署状态、测试版本和实际验证结果应在对应发布记录中单独说明。

## 使用入口

- `/governance`：当前账号当天的模型准入次数、保守 Token 配额、供应商报告的已知用量、调用状态及请求关联编号；管理员额外查看网关状态。
- 主对话历史：按账号保存 Manus 会话和轮次；同一个 `requestId` 复用已有结果，不自动重放。
- 主对话参考便签：由用户明确保存、修改或清空，最多 4000 字；不会授予工具权限，也不代表自动长期记忆。
- Coding 工作区：保留真实文件事件、审批与取消；每次模型 HTTP 请求先向 Java 请求准入，包括 pi 的上下文压缩请求。

## 模型准入与持久账本

Java 模型调用和 Coding 模型请求共用 `ModelGovernance`。控制流程为：

1. 获取服务端认证的账号身份，校验并发、每日请求次数、剩余保守 Token 配额及熔断状态。
2. 将 RUNNING 记录及预留额度写入账号日账本；写入失败时不发送模型请求。
3. 执行一次模型请求。系统 OpenAI、BYOK 和 DashScope 的 SDK 隐藏重试关闭；Coding SDK 重试也关闭。
4. 记录模型结果状态、可获得的用量及耗时，释放并发槽位。不会因超时或断连自动重复付费请求。

Spring AI 的自动工具循环由治理层逐轮执行，每轮重新准入，最多 20 轮，支持工具 `returnDirect`。Manus 已自行管理循环，因此不会重复执行工具。需要内部工具执行的流式接口返回最终结果事件，不提供逐 Token 展示；普通非工具流仍支持增量输出。

### 默认配置

以下为 Spring 配置键，可通过应用配置文件或标准 Spring 环境配置覆盖。额度对管理员与普通账号均生效。

| 配置键 | 默认值 | 含义 |
| --- | --- | --- |
| `app.governance.dir` | `tmp/governance` | 必须备份的日账本目录 |
| `app.governance.account-concurrency` | `2` | 每个账号正在进行的模型请求上限 |
| `app.governance.global-concurrency` | `8` | 当前 Java 实例正在进行的模型请求上限 |
| `app.governance.daily-requests` | `100` | 每账号每天准入的请求次数；一次任务可能有多次模型请求 |
| `app.governance.daily-tokens` | `200000` | 每账号每天的保守 Token 配额，并非供应商账单额度 |
| `app.governance.output-tokens` | `4096` | Java 模型请求的最大输出参数 |
| `app.coding.global-concurrency` | `8` | 当前实例同时运行的 Coding 任务上限 |
| `app.coding.context-window` | `64000` | Coding 声明的上下文窗口；须符合实际所选模型 |
| `app.coding.timeout-seconds` | `900` | Java 对 Coding 子进程的总等待上限；Node 每轮还有自身时间限制 |

日界使用 **UTC**。Coding 的模型输出上限由运行时上下文配置决定，最高 8192，不由 Java 的 `output-tokens` 控制；其完整模型请求正文与输出上限均纳入同一日配额准入。Coding 每轮模型 HTTP 请求最多 100 次（包含压缩），工具调用最多 80 次。上限是停止条件，不代表一定能完成相同长度的任务。

### 配额、实际用量与状态分别统计

- `reservedTokens`：发送前根据文本、工具上下文或请求正文以及最大输出估算的预留量，不是厂商 tokenizer 的精确结果。
- `inputTokens` / `outputTokens`：供应商明确报告的用量。缺失时为 `null`，不使用 SDK 的默认零值冒充免费调用。
- `chargedTokens`：每次按 **预留估算与有效报告总量的较大值**占用配额，成功短回答也不返还预留量，避免不可信 BYOK 端点以伪造零用量绕过预算。
- `knownTokens`：已知报告值的汇总，和保守配额占用分开；失败时的部分报告值不证明完整账单已经拿到。
- `costStatus=UNKNOWN`：尚未配置并验证价格表，没有金额预算或账单对账能力。pi 模型定义中的成本零值属于 SDK 配置占位，不能用于认定调用免费。

`SUCCEEDED` 表示请求在当前协议下完成，不表示模型回答正确；它仍可能没有 usage。`FAILED` / `CANCELLED` 也可能有部分已知用量；`UNKNOWN` 表示无法确认最终请求结果。状态与计量是否完整是两件事。

已经被供应商接受的请求可能继续执行并计费。取消、超时、断开页面或本地进程终止不保证供应商停止收费。使用供应商自身的账号额度与费用限制作为额外控制。

### 故障与恢复

同账号同模型连续失败 3 次后暂停新请求 30 秒，随后只放行一个探测请求；成功则恢复。熔断状态属于当前进程内存，不是分布式故障路由，也没有自动切换其他账号的 Key 或备用模型。

结算写盘失败时保留待结算记录并向调用方报告失败。后续准入、汇总或事件查询先尝试补写；存储仍不可用时拒绝新模型请求。恢复只重试**账本写入**，不会再次调用模型或重复扣账。服务重启后，原 RUNNING 记录转为 UNKNOWN 并保留预留额度，不推测实际 Token 或重放请求。

账本为 `tmp/governance/<owner>/<UTC-day>.json`。当前页面显示当天汇总和最近 100 条记录；历史日文件仍需按备份与保留策略管理。删除账本会丢失额度与审计证据，不应作为正常“恢复”方式。

## 网关、请求关联与运行指标

网关为请求生成新的关联 ID，并将认证账号和 ID 传给后端。模型事件另有独立 `traceId`；后台任务显式传递账号和关联 ID，Reactor 流使用认证上下文，缺少身份时拒绝调用。

应用日志记录状态、类型、数量、耗时和关联 ID，避免输出提示词、回答、工具参数、完整 URL 或凭据。共享 OpenAI 使用不读取响应正文的安全错误处理器。当前原生 DashScope SDK 的既有 API 对象无法直接替换处理器，因此移除重试监听器并关闭 `org.springframework.ai.retry.RetryUtils` 日志；治理层向调用方抛出无原始 cause 的安全错误。不要在生产环境开启供应商 SDK、HTTP wire 或请求正文 DEBUG 日志；这不是对所有第三方组件的完整 DLP 保证。

| 网关环境变量 | 默认值 | 范围 |
| --- | --- | --- |
| `GATEWAY_MAX_CONCURRENT` | `64` | 当前网关并发 HTTP 请求 |
| `GATEWAY_USER_CONCURRENT` | `12` | 每账号并发 HTTP 请求 |
| `GATEWAY_MODEL_CONCURRENT` | `8` | 当前网关模型相关入口的并发 HTTP 请求 |
| `GATEWAY_USER_MODEL_CONCURRENT` | `2` | 每账号模型相关入口的并发 HTTP 请求 |
| `GATEWAY_USER_RPM` | `240` | 每账号每分钟 HTTP 请求 |
| `GATEWAY_USER_MODEL_RPM` | `20` | 每账号每分钟模型相关入口请求 |

网关限流只覆盖 HTTP 生命周期。已经提交的后台任务还需要 Java/Node 模型准入和 Coding 任务并发限制，不能用短暂的提交接口连接数代替后台任务数。

管理员接口 `/api/ops/health` 查看网关配置与准入状态，`/api/ops/metrics` 查看路由分组的状态计数、拒绝次数及最近 512 个完成请求的延迟 P95。指标是单个网关进程内的快照，重启后重新计数；它们不是统一分布式 Trace、全依赖健康探测、告警平台或经过验证的 SLO。

## HTTPS 与命令隔离

生产配置示例仅使用占位域名：

```dotenv
AGENT_PRODUCTION_MODE=true
PUBLIC_ORIGIN=https://agent.example.com
SESSION_COOKIE_SECURE=true
GATEWAY_TLS_MODE=reverse-proxy
PUBLIC_BIND=127.0.0.1
```

该模式要求可信 TLS 反向代理，网关只监听 loopback。也可使用 `GATEWAY_TLS_MODE=direct` 并提供 `GATEWAY_TLS_CERT` / `GATEWAY_TLS_KEY`；证书与私钥属于私有部署配置，禁止提交仓库。生产模式校验配置不足时拒绝启动，但证书的客户端信任、域名和到期状态仍需部署者实际验证。内部服务令牌不能交给浏览器，后端不可绕过网关暴露给不可信网络。

Coding 的 `bash` 与 Java 终端工具只通过经探测可用的 **Linux bubblewrap + prlimit** 执行。隔离环境使用无网络的命名空间、非 root 身份、移除能力、只读项目快照和受限临时目录，包含 CPU、地址空间、进程/文件数、单文件大小、输出及等待时间限制。宿主敏感目录和受保护文件不挂载；不能把命令修改当作已写回项目的结果，实际改文件应使用受审批的 write/edit。

隔离不可用、平台不支持或未授权时关闭命令能力，**不回退宿主 shell**。这仅描述命令子进程：Java、pi 编排进程、模型网络连接和文件工具并未全部运行在同一隔离容器中。它不是可直接开放给任意攻击者的完整多租户执行平台，也不等于 cgroup 的整机 CPU/内存/磁盘配额。

## 上下文与跨会话资料

Manus 持久保存账号会话、状态和有限回答；保留最近 8 个成功轮次的有界文本，早期轮次使用注明截断的原文节选。失败/中断轮次不作为成功历史继续输入。每会话最多 100 轮；重复编号只返回原状态或原结果；重启不会自动继续模型执行。

用户参考便签可跨主对话使用，但只由用户显式维护。它不是自动语义记忆、向量化长期记忆或事实核验。Coding 启用 pi 上下文压缩，压缩本身会调用模型并消耗同一配额；声明的上下文窗口需要与所选厂商模型相符。没有经过真实模型长任务验证，就不能声称已解决所有 20–50 轮任务的遗忘或完成质量问题。

## API 与维护入口

后端配置默认带 `/api` 前缀：

| API | 内容 |
| --- | --- |
| `GET /api/ai/governance` | 当前账号当日汇总与限制 |
| `GET /api/ai/governance/events` | 当前账号当日最近 100 条安全模型事件 |
| `GET /api/ai/manus/conversations` | 当前账号主对话列表 |
| `GET /api/ai/manus/conversations/{id}` | 对话内容与轮次状态 |
| `POST /api/ai/manus/conversations/{id}/cancel` | 请求停止当前任务，保留历史 |
| `DELETE /api/ai/manus/conversations/{id}` | 删除非运行中的会话 |
| `GET/PUT /api/ai/manus/memory` | 读取、修改或清空显式参考便签 |

安全日志与用量账本不保存对话正文，不代表整个应用不保存正文：用户选择保存的聊天历史、伙伴产物、pi 会话和参考便签仍包含私有材料。备份访问权限、加密及保留期需要部署者维护。升级时备份账号、模型密文与主密钥、业务文件，以及新增的治理账本和 Manus 会话；不要以清空历史代替排查问题。

## 尚未覆盖的生产要求

- 当前仅支持**单实例**：文件账本、进程内并发与熔断没有分布式锁，不能用多个 Java 实例共享目录获得正确集群额度。
- 没有自动任务路由、跨供应商降级、Key 池、价格对账和金额硬预算。
- 外部 Embedding、独立 NarrativePPT 服务的模型调用和费用不在此账本中；旧版单次技能/出行功能使用共享 Java 模型时经过模型准入，但 BYOK 配置体验仍与主对话入口不同。
- 没有完整集中告警、自动恢复编排、提示注入/数据外传对抗认证、DLP 或通用内容审核。
- 没有宣称当前源码已经通过公网发布、目标并发压测、真实付费厂商矩阵或通用模型质量验收。

验证应分别记录单元/契约测试、真实协议测试、隔离环境验证、浏览器验证、故障注入和部署验收；模拟通过不能替代真实内容质量与容量测试。
