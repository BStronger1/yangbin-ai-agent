# 来源检查与质量回归第三版

日期：2026-10-16。针对 `code/yu-ai-agent` 的出行任务与保存方案。

## 实现范围

- 保存方案时运行 `PlanQualityService.assess`，结果随不可变方案版本、任务检查点保存。报告包含规则版本、检查时间、地点名称与引用对应数、逐项来源、待核实事项及明确限制。
- 新任务与直接规划/修改方案共用同一检查器；网页与PDF显示报告。不会为了检查额外调用模型，也不自动删除或改写原方案文本。
- `REVIEW_REQUIRED` 表示规则发现需核实的问题；`CHECKED_WITH_LIMITATIONS` 只表示规则执行完成且没有warning，绝不代表所有内容真实。费用仍为估算；地图记录不证明当天营业、票价或交通耗时。
- 历史方案缺少quality保持原数据，不把缺失报告当成检查通过；页面明确显示历史未检查。执行中的新草案显示检查尚未完成。
- 生成提示词补充完整候选名称、日预报粒度、不得无依据引入公共卫生政策等限制。提示词不能保证模型始终遵守，规则也不是通用语义事实核验。

## 验收方式

- 固定样例检查规则的正例与负例，并保留上一版真实模型输出的防疫提醒作为回归样例；输出到 `target/quality-evaluation.json`，CI保存为 `quality-rule-evaluation` artifact。这不是自由文本模型准确率评测。
- 集成测试覆盖任务/方案报告一致、落盘后读取、重启、警告进入PDF、旧JSON不补写、直接规划版本互不覆盖。
- 真实验收：`deploy/turing/quality-smoke.py prepare` 创建一个新任务并等待确认；浏览器确认后运行 `verify` 收集报告/PDF，成功路径2次逻辑模型调用。

- 回退边界：新方案/任务增加quality字段；旧二进制未保证能读取新格式。部署更新保留数据，回退业务版本前应备份并验证迁移，不能直接让旧版本读取新任务目录。

## 已知限制

- 地点对应只比较引用编号和规范化完整名称，不能证明所有自然语言活动描述正确、未夹杂其他地点，或该地点现实可用。
- 天气日期对应不证明每一句天气推断；日预报不能支持准确小时天气或全天连续天气。历史快照不是最新实况。
- 政策/价格/营业/交通声明检测只覆盖有限明确措辞，会有漏报和误报；泛化语义检查、人工确认闭环、自动纠错重规划和真实质量基准尚未实现。
- 规则发现warning仍可保存并导出，报告必须随结果展示；执行成功不等于来源完全可信。
