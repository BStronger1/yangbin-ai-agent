# 0.4.0 工作台、候选与恢复同步

本版把博客版之后的 Work 证据转交、Coding 独立候选、持久回执、测试生命周期修复及应用内切页恢复整合到同一发布源码。MiniMind 路由训练不在本版范围，独立 Pi/SWE 实验分数也不作为本版线上质量承诺。

## 用户可见变化

- Work 可依据原始行核对结果，并明确选择材料、目标项目和用途后转交 Coding。
- Coding 的运行状态、候选保存、设备回执和测试结论分别显示。明确未写入的错误可以纠正，未知副作用不会自动重放；目标失败不会被无关绿灯覆盖。
- 应用内切到 Chat 或设置后保留 Coding 工作台连接，返回可继续查看原任务。关闭窗口、刷新、退出账号或设备休眠仍需要恢复核对。
- Windows 0.4.0 在私有候选中修改本机项目，原目录保持不变；审阅后下载补丁自行合并。候选模式不启动本机程序，普通浏览器本机目录仅支持读取。旧版客户端需升级，不能退回不具备候选回执的直接写入。
- iOS 0.4.0（build 4）使用同一生产工作台的服务端项目与候选下载。CI提供模拟器测试和真机架构的未签名IPA，个人签名及真机安装单独验证。

## 构建与发布

使用Java 21+、Node 22.19+和Python 3.12+。构建MCP模块后运行Java测试并打包，构建前端；运行 `python tools/package_release.py --out <新的绝对输出目录> --label v040-YYYYMMDD` 生成JAR、前端、独立Coding运行时及SHA256清单。Windows可通过 `YANGBIN_PACKAGE_DIR` 指定新目录后运行 `npm run package`，已有目录不会覆盖。

服务器发布需核对当前版本和活动任务，保留账号、用户数据、模型配置、旧资源及可回滚运行时，验证新运行时后再切换服务。源码提交、远端CI、网站上线、下载指针和iPhone真机安装是独立状态，以各自实际收据为准；本文不代替线上或设备验收。

公开发布提交从既有GitHub主分支创建，只包含产品、产品测试和构建说明。独立SWE评测脚本、冻结清单及私有验收证据保留在维护者工作区，不随本次GitHub更新发布。
